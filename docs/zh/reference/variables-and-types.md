# 变量与类型

## 变量与可变性

```simy
let damage = 10                        // 不可变（默认，无前缀）
let mut timer = 0                      // 可变（mut 前缀，一眼可见）
let target: entity = @e[type=creeper]  // 类型后置，可推断时省略
const MAX_HEALTH = 20                  // 编译期常量，直接内联，不占计分板
```

**可变性比例策略**：不可变约 80%（配置、中间值），可变约 20%（计时器、游戏状态）。
可变变量必须显式写 `mut`，并声明其存储位置。

**编译层降级**：

| 声明         | 降级                         |
| :----------- | :--------------------------- |
| `const`      | 内联消失，不占任何运行时存储 |
| 不可变 `let` | 常量折叠 / SSA 优化          |
| `mut`        | `scoreboard` / `storage`     |

## 类型系统

类型分三层：**基础类型**、**Minecraft 领域类型**（一等公民）、**复合类型**。
所有类型名均**上下文识别、不保留**——它们只在类型位置生效，故 `tag @s add foo` 等命令不受影响。

### 基础类型

| 类型    | 说明                             | 底层映射                          | 字面量示例       |
| :------ | :------------------------------- | :-------------------------------- | :--------------- |
| `num`   | 32 位整数（计分板原生能力）      | `scoreboard` (int)                | `42`、`-3`       |
| `float` | 浮点（编译为定点数，×1024 缩放） | `scoreboard` 缩放 / `storage` NBT | `3.14`           |
| `bool`  | 布尔，编译为 0/1                 | `scoreboard`                      | `true` / `false` |
| `str`   | 字符串                           | `storage` NBT / `tellraw` 内联    | `"hello"`        |

> `num` 是默认数字类型，因为计分板是整数（32 位，范围见[数值范围与溢出](#数值范围与溢出)）。`float` 在编译期自动做定点数缩放
> （乘 1024 存入 scoreboard，再用 `scale=0.0009765625`，即 2⁻¹⁰，换算回来），用户无感知。

> `bool` 在语义上有两种角色：用 `let` **绑定**的布尔是*值布尔*，存为 0/1 计分板；而像
> `counter >= 100` 这样的内联条件是*测试表达式*，直接降级为 `execute if`，不占存储。详见
> [控制流与作用域](/zh/reference/control-flow#条件测试表达式与值布尔)。

### 领域类型（一等公民）

| 类型       | 说明                                         | 底层映射          | 字面量示例                          |
| :--------- | :------------------------------------------- | :---------------- | :---------------------------------- |
| `entity`   | 已解析的具体实体（可读属性 `target.health`） | 选择器 / UUID     | `@a[distance=..10]`                 |
| `selector` | 选择器表达式本身（延迟求值）                 | 原样嵌入命令      | `@e[type=zombie]`                   |
| `pos`      | 坐标（含 `~` 相对坐标）                      | `storage` 或内联  | `~ ~1 ~`、`(0, 64, 0)`              |
| `vec3`     | 向量（与 `pos` 配合的运动量）                | `storage`         | `(0.5, 1.0, -0.2)`                  |
| `block`    | 方块 ID + 方块状态                           | 内联 ID           | `minecraft:chest[waterlogged=true]` |
| `item`     | 物品 ID + NBT / 组件                         | 内联              | `minecraft:diamond_sword`           |
| `team`     | 队伍                                         | `scoreboard` 原生 | `"adventure"`                       |
| `tag`      | 标签                                         | `scoreboard` 原生 | `"boss"`                            |
| `nbt`      | 逃生舱：任意原始 NBT                         | `storage` 原样    | `{Health:10f}`                      |

> **`entity` vs `selector`**：`entity` 表示“已解析的具体实体”（可读属性、可传参）；
> `selector` 是“选择器表达式本身”（延迟求值，可传入 `execute`）。这个区分让编译器能做更激进的优化。
>
> **`nbt` 逃生舱**：保证 DSL 永远不会被 MC 新版本的新字段卡住——任何无法抽象的东西都能以原始 NBT 传递。

### 复合类型

| 类型        | 说明                                                     | 底层映射                  |
| :---------- | :------------------------------------------------------- | :------------------------ |
| `list<T>`   | 列表                                                     | `storage` NBT list        |
| `map<k, v>` | 映射（如 `map<str, num>`）                               | `storage` NBT compound    |
| `option<T>` | 可空（配合未来 `?` 传播，“实体可能不存在”）              | `scoreboard` 存在位 + 值  |
| 组件实例    | 用户定义的组件类型（见[组件](/zh/reference/components)） | `tag` + 多个 `scoreboard` |

### 类型推断

- `let damage = 10` 自动推断为 `num`。
- 跨 scoreboard 的值默认 `num`。
- `if` / `elif` / `else` 表达式的类型取各分支的**公共类型**；分支类型不一致，或「有值」与「无值」混用，都会报错。
- 函数体的值必须与声明的 `-> T` 一致（见[隐式返回](/zh/reference/functions#隐式返回)）。
- 进 `storage` 的复杂结构需要显式类型注解：

```simy
let scores: map<str, num> = { "kills": 0, "deaths": 0 }
```

## 数值范围与溢出

整数在原版里不是无限的，而且**位数随存储位置变化**——`num` 落在计分板上，范围就由计分板决定：

| 存储位置        | 底层类型                  | 范围                                            |
| :-------------- | :------------------------ | :---------------------------------------------- |
| 计分板（`num`） | 32 位有符号整数           | −2³¹ … 2³¹−1                                    |
| `storage` NBT   | byte / short / int / long | −2⁷…2⁷−1 / −2¹⁵…2¹⁵−1 / −2³¹…2³¹−1 / −2⁶³…2⁶³−1 |
| `pos`、`vec3`   | double（IEEE-754）        | x、z ∈ [−3×10⁷, 3×10⁷)，y ∈ [−2×10⁷, 2×10⁷)     |

2³¹ 这个上界是原版行为，不是可调参数；`storage` 的 long 到 2⁶³，是本作能表达的最大整数。`pos`、`vec3` 本身是 double，整数可精确表达到 2⁵³，表里的坐标界则是命令参数另加的。

**溢出会环绕。** 计分板运算在 32 位内进行，越界**不报错**，而是环绕（等同 Java 的 `int`）：

```simy
let mut hp = 2_147_483_647  // 2³¹ − 1，计分板上界
hp += 1                     // → −2³¹，环绕而不是报错
```

Simy 不掩盖这一点，但会把编译期看得见的部分提前：**字面量与 `const` 的越界在编译期报错**，运行时的值仍与 Minecraft 一致地环绕。

**三条容易踩的语义。** 计分板运算直接落成原生命令，行为沿用游戏的定义：

| 运算         | 语义                         | 注意                         |
| :----------- | :--------------------------- | :--------------------------- |
| `a / b`      | **向下取整**（floor）        | 不是向零截断：`-7 / 2 == -4` |
| `a % b`      | `Math.floorMod`（1.13.1 起） | 结果符号跟随除数             |
| 浮点 → `num` | **向下取整**后存入           | `-1.5` 会存成 `-2`           |

**定点数用 2 的幂缩放。** `float` 是 ×1024（2¹⁰）的定点数，所以计分板那 ±2³¹ 要先除以 2¹⁰：

- 单个 `float` 的范围是 **±2²¹（约 ±2.10×10⁶）**；
- 两个 `float` 相乘会变成 ×2²⁰ 缩放，所以 `|a · b|` 要留在 **2¹¹ = 2048** 以内，否则中间结果就溢出 32 位了。

乘法因此必须显式修正缩放（乘完再 `÷ 1024`，也就是右移 10 位，代价是丢掉低位的精度）。

**要更大的整数**只有两条路：

- 放进 `storage` 的 long（−2⁶³ … 2⁶³−1）；
- 或者用「高位 / 低位」两个计分板拼出一个大数——数据包社区的老办法，`list<T>`、`map<k, v>` 正好是它的载体。
