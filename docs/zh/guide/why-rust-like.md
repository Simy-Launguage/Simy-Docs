# 为什么 Simy 长得像 Rust

很多人第一眼看到 Simy，都会注意到它很像 Rust。这自然会引起疑问：Rust 以**难**著称，而 Simy 的目标是**易学**。这一页解释我们到底借用了什么、又刻意舍弃了什么，以及为什么。

::: tip 一句话版本
Simy 借用的是 Rust 的**表层语法**，不是它的**内存模型**。这里没有所有权、没有借用、没有生命周期——因为根本没有内存要管理。我们真正想要的三个特性是：**静态强类型**、**类型后置**、**花括号**，它们让代码结构规范、可读性高。
:::

## 与「内存安全」无关

Rust 最大的卖点是「无 GC 的内存安全」。Simy 和这件事毫无关系：

- Simy 编译成 `mcfunction` 和 JSON，没有手动内存管理，也没有分配器要操心。
- 数据包运行在 Minecraft **内部**，它的「状态」是计分板目标与 storage NBT，不是指针和缓冲区。
- 因此 Simy **没有所有权规则、没有借用检查器、没有生命周期标注**。Rust 里最容易吓退初学者的部分，这里统统不存在。

我们抄的是 Rust 代码的**形状**，不是它的安全机制。

## 这套文档写给谁

Simy 是面向 Minecraft 数据包开发的**领域特定语言（DSL）**。它的用户是地图作者、服务器管理员、学生和爱好者——其中相当一部分**并不是职业程序员**。好的 DSL 应该降低门槛，而不是抬高门槛。所以每个语法决策背后都有一个共同的问题：

> 这能不能帮一个非程序员，在半年后依然读懂这段代码？

Rust 风格的语法能通过这个检验，原因有三。

## 我们真正借用的东西

### 1. 静态强类型

在动态语言里，一个写错的选择器就只是一段字符串，直到运行时才出问题——而报错出现在 Minecraft 里，常常让人摸不着头脑。Simy 则分得清 `entity`、`pos` 和 `str`，于是编译器能在你**启动游戏之前**就指出出错的那一行。

对 Minecraft 来说这点尤其重要，因为它的领域里充满了真正不同的值类型。见[变量与类型](/zh/reference/variables-and-types)。

### 2. 类型后置

类型写在它所描述的东西**后面**：

```simy
let target: entity = @e[type=creeper]
let damage = 10
```

从左往右读就是「一个 `target`，它是一个 `entity`」。你真正关心的名字在前，类型只是末尾的标签，而且**能推断时可以直接省略**。新手少打很多字，需要时信息又都在。见[变量与类型](/zh/reference/variables-and-types)。

### 3. 花括号与结构

`{ }` 让作用域边界清晰、没有歧义：

```simy
if counter >= 100 {
    tellraw @a "连击达标！"
}
```

- 块的结束是显式的——不存在「只靠缩进」引发的争论，不会有 Tab 与空格的坑，粘贴代码也不会悄悄改变含义。
- 花括号天然配合 Rust 的**结构化控制流**，这正是 Simy 用来替代深层嵌套 `execute` 的手段。见[控制流与作用域](/zh/reference/control-flow)。

## 为什么不能以类 Python 的语法打底？

Python 的语法确实友好，我们也乐于借鉴。但把 Python 的**模型**拿来做 Minecraft DSL 的底子，会在好几处带来摩擦，而「类型」只是其中一处。

::: info 我们确实借鉴了 Python
而且不少——Python 在很多地方是对的：

- 用 `elif` 而不是 `else if`——更短，整条分支链保持同一层级
- `for x in …` 迭代
- 直白的 `print` 式调用，而不是 `println!` 宏
- 条件免括号

我们用 Python 的**表层**想法来减少负担；不采用的，是它的**模型**——动态类型与缩进分块，原因见下。
:::

### 类型不合身

- **Python 是动态类型。** 实体、选择器、坐标都只是字符串，没有东西阻止你把坐标传成实体。
- **Minecraft 充满领域类型**——`entity`、`selector`、`pos`、`vec3`、`block`、`item`、`team`、`tag`、`nbt`。只有把它们建模成一等类型，编译器才能一边**检查**你的代码，一边做**优化**。
- **注解是可选、外挂的。** Python 里类型标注只是提示；在 Simy 里它是语言的一部分，工具链可以信任它。

### 缩进很脆弱

Python 只靠缩进划分块。在整洁的文件里这看着很舒服，但它让「看不见的东西」变得要紧：

- **不可见字符会改变语义。** 一个多余的 Tab、混用 Tab 与空格，或者——用中文输入法时非常常见——一个全角空格（`　`）或全角冒号（`：`），都会悄悄改变甚至弄坏程序，而报错往往指不到真正的原因。
- **复制粘贴会失真。** 在聊天、论坛或 Discord 里分享的代码片段常常丢掉行首空白，粘过来的代码就不再是原来的行为。
- **深层嵌套看不见。** 超过几层后没有收尾符号给眼睛定位，只能靠数空格确认块到哪里结束。

Simy 改用 `{ }`：块的结束是显式的。而且标识符字符集固定为 ASCII，全角字符会变成一个明确的错误，而不是一团迷雾。

### 报错与工具更吃力

- **缩进敏感的语法更难从错误中恢复。** 解析器要单独跟踪 indent/dedent，于是「unexpected indent」这类报错和自动修复——恰恰是新手最依赖的东西——更难做好。
- **动态类型让编辑器帮不上忙。** 没有任何东西能告诉你 `@e[type=zombie]` 不该出现在需要数字的位置；有了 Simy 的类型，工具可以。
- **显式的花括号让格式化器和 lint 有一份无歧义的结构可改写。**

### 语言体量超过了问题本身

Python 是通用语言：对象、类、异常、导入、生成器、装饰器……而一个数据包需要的是一套小而可预测的表层。DSL 应该像「一页就能学会」的东西，而不是一门要慢慢长进去的语言。

::: info 这不是在贬低 Python
以上并不是说 Python 设计得不好——它是为通用性和整程序的可用性调优的。只是这些取舍放到 Minecraft DSL 上并不划算。
:::

一句话：Python 的简单是真的，但它是为 Python 的目标调优的。对数据包来说，显式的花括号加一套真正的类型系统，减少的困惑远多于增加的负担。

## 我们刻意砍掉的 Rust 语法

全盘照搬 Rust 就本末倒置了。既然 Simy 只是一门 DSL，那就留下规范，丢掉仪式感：

| Rust                                       | Simy                                               | 原因                                          |
| :----------------------------------------- | :------------------------------------------------- | :-------------------------------------------- |
| `println!(…)` 宏 + 格式串 + 各种格式化选项 | Python 那样直白的 `print` 调用，**不提供参数选项** | 打印一个值，不该先学宏和格式串                |
| `else if` 多层分支                         | `elif`（**借鉴自 Python**）                        | 更短，且每个分支都保持在同一缩进层级          |
| 每条语句末尾的 `;`                         | 语句以**换行**结尾                                 | 少记一条标点规则；一行一句                    |
| 所有权、借用、生命周期                     | 全部移除                                           | 根本没有内存要管理                            |
| `struct` + `impl` + `trait`                | `component`（状态 + 行为）                         | 只保留 Minecraft 真正需要的形状               |
| 宏（`!`）                                  | 无                                                 | 没有元编程要学                                |
| `pub`、`mod`、`use`、crate                 | 不需要                                             | 数据包就是一套扁平的文件布局 + 生成的命名空间 |
| 到处是泛型                                 | 仅 `list<T>`、`map<k, v>`、`option<T>`             | 够表达真实数据，又不会变成类型体操            |
| `match`、枚举、闭包、迭代器                | 暂不提供                                           | 保持表层语法足够小                            |

## 我们遵循的准则

> **留下让代码可读的「结构」，丢掉只在系统编程里才划算的「仪式」。**

这就是全部思路。花括号、类型后置、静态类型给 Simy 一个规范、易扫读的形状；而那些纯粹为了让一门内存安全的系统语言运转起来才存在的东西，都被去掉了。如果目标真的是「像 Rust」，我们就会把难的部分也留下——我们只留下了对新手有帮助的部分。

## DSL 就在你我身边

人们容易用「能表达多少东西」来衡量一门语言，而 Simy 刻意反其道而行——但它并不孤单。计算机领域里最有影响力的语言，很多都不是通用语言：

- **HTML** 描述文档；
- **SQL** 查询数据库；
- **Excel 公式** 计算表格；
- **CSS** 为网页排版；
- **正则表达式** 匹配文本；
- **Makefile / Dockerfile / .gitignore** 配置工具。

它们都很小、很专注，而且刻意**不是图灵完备**的；每一个都为某个领域打开了大门，让不是职业程序员的人也能上手。DSL 并不是「差一等的通用语言」，而是一种不同的工具——在它擅长的领域里往往更好用。Simy 很自豪成为中之一。
