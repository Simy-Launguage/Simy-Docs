# 语法从何而来

Simy 不是一门从头开发的语言。它的表层每一处都取自别处——因为 Simy 是面向 Minecraft 数据包的**领域特定语言**，不是通用语言，而好的 DSL 应该好读、不易误读。

这一章把表层语法逐项对应到它的来源，并说明我们刻意舍弃了什么。它不是替某一门语言辩护，而是一次取舍之旅。

::: tip 一句话版本
我们同时借鉴了**多门语言的表层想法**——Rust 的花括号、`fn` 与静态类型，Python 的 `elif` 和 `for … in`，函数式语言与 [Revo](https://revo.lung.fyi/) 的表达式化风格——而一切真正属于 Minecraft 的概念，都用 Minecraft 自己的词汇来表达。
:::

## 表层语法的来源地图

| Simy 特性                                          | 来源                            |
| :------------------------------------------------- | :------------------------------ |
| `{ }` 块、`fn`、`mut`、`->`、`//` 注释             | Rust                            |
| 静态类型，类型后置                                 | Rust                            |
| `component`（状态 + 行为合一）                     | Rust 的 `struct` + `impl`，摊平 |
| 用 `elif` 而非 `else if`                           | Python                          |
| `for x in …` 迭代                                  | Python                          |
| 直白的 `print` 式调用，不用宏                      | Python                          |
| 条件免括号                                         | Python                          |
| 块与 `if` **产生值**；函数体最后一个表达式即返回值 | 函数式语言 / Revo               |
| 用 `\|>` 竖排 `execute` 子句                       | 函数式管道 / Revo（含义已变）   |
| 默认不可变                                         | Rust 与函数式语言               |
| `@a`、`~ ~1 ~`、`scoreboard`、`storage`、NBT       | Minecraft 本身                  |
| `entity`、`pos`、`block`、`item`…… 一等类型        | Minecraft 本身                  |

## 从 Rust 借了什么

Rust 留下的印记最深，所以值得说一说我从 Rust 借鉴了什么，舍弃了什么。Simy 只是借用 Rust 的**表层语法**，而不是它的**内存模型**：这里没有所有权、没有借用、没有生命周期，因为根本没有内存要管理。数据包的「状态」是计分板目标与 storage NBT，不是指针和缓冲区。

### 1. 静态强类型

在动态语言里，一个写错的选择器只是一段字符串，直到运行时才出问题——而报错出现在 Minecraft 里，常常让人摸不着头脑。Simy 则分得清 `entity`、`pos` 和 `str`，于是编译器能在你**启动游戏之前**就指出出错的那一行。见[变量与类型](/zh/reference/variables-and-types)。

它还有一处不那么显眼的好处：**加新类型很省事**。类型是集中声明、由编译器统一解释的，所以想引入一个新概念——不管是 Minecraft 新版本冒出来的东西，还是我们自己想抽象的形状——只要在类型表里加一条，编译器就替你在所有地方完成检查与优化：调用点不必改动，也不会悄悄退化成一段字符串。而且类型名**上下文识别、不保留**，加一个新名字不会撞上已有的命令。

### 2. 类型后置

类型写在它所描述的东西**后面**：

```simy
let target: entity = @e[type=creeper]
let damage = 10
```

从左往右读就是「一个 `target`，它是一个 `entity`」。你真正关心的名字在前，类型只是末尾的标签，而且**能推断时可以直接省略**。

### 3. 花括号与结构

`{ }` 让作用域边界清晰、没有歧义，天然配合用来替代深层嵌套 `execute` 的结构化控制流：

```simy
if counter >= 100 {
    tellraw @a "连击达标！"
}
```

「只靠缩进」要付的代价——Tab 与空格混用、全角字符、粘贴时丢失行首空白——放到下一节，和 Python 的缩进模型一起说。

## 从 Python 借了什么

Python 的语法确实友好，我们也乐于借鉴——只是不把它的**模型**当作底子。表层上，借的就是来源地图里列的那几条：`elif`、`for x in …`、直白的 `print` 式调用、条件免括号；其中 `elif` 最划算——比 `else if` 短，而且整条分支链都停在同一层级。

不采用的，是它的**模型**——动态类型与缩进分块：

- **类型不合身。** 实体、选择器、坐标都只是字符串，没有东西阻止你把坐标传成实体。Minecraft 充满真正不同的领域类型，只有把它们建模成一等类型，编译器才能一边**检查**你的代码，一边做**优化**。
- **缩进很脆弱。** 一个多余的 Tab、混用 Tab 与空格，或者——用中文输入法时非常常见——一个全角空格（`　`）或全角冒号（`：`），都会悄悄改变甚至弄坏程序，而报错往往指不到真正的原因。花括号是显式的；加上标识符字符集固定为 ASCII，全角字符会变成一个明确的错误，而不是一团迷雾。
- **复制粘贴会失真。** 在聊天或论坛分享的代码片段常常丢掉行首空白，粘过来的代码就不再是原来的样子。
- **语言体量超过了问题本身。** Python 带着对象、类、异常、导入、生成器、装饰器……而一个数据包需要的是一套小而可预测的表层——「一页就能学会」，而不是一门要慢慢长进去的语言。

::: info 这不是在贬低 Python
以上并不是说 Python 设计得不好——它是为通用性和整程序的可用性调优的。只是这些取舍放到 Minecraft DSL 上并不划算。
:::

## 哦，还有函数式语言 ?!<(°0°)>!?

有两个想法来自函数式传统——以及最近一门实验性动态语言 [Revo](https://revo.lung.fyi/)，它自述「为编程的乐趣而生」，并且**一切皆表达式**。

### 块与 `if` 产生值

`{ }` 块是一个表达式，其值就是块内最后一个表达式的值；`if` / `elif` / `else` 也会产生值——即实际执行的那个分支的值：

```simy
let label = if hp <= 0 { "dead" } else { "alive" }
```

声明了返回类型的函数，其函数体的值就是返回值，因此末尾通常不必写 `return`：

```simy
fn distance_multiplier(victim: entity) -> num {
    2
}
```

`return` 保留给**提前退出**，而不是正常出口。见[函数](/zh/reference/functions#隐式返回)。

很多现代的命令式语言也有隐式返回，其实是延续了函数式语言“Everything is Something”的思想

### 用 `|>` 竖排 `execute` 子句

```simy
execute as @s
    |> at ~ ~1 ~
    |> if score $timer matches 1..100
    |> title @s actionbar "tick"
```

我在设计 Simy 语法时了解到 Revo 有下面这样的写法。

```revo
let x = "hello"
  |> _:upper()
  |> _:sub(1, 2)
  |> assert_eq("el")
```

`|>` 是函数式语言常有的符号，通常指将前一个表达式的结果送入下一个函数。

我想到虽然 execute 链没有值传递，但也是从左往右动宾交替，像一节节管道，为什么不能用 `|>` 把“管道”截开换行呢？使用声明式的链式语法，将深层嵌套的 execute 链变成单层、线性、可读的“子句序列”。

值得强调的是，在函数式语言与 Revo 里，`|>` 是真正的运算符，把左侧的值传递给右侧的函数；在 Simy 里它只是**续行标记**：不携带任何语义、等价于一个空格，存在的唯一理由就是让 `if` 这类 `execute` 子句可以单独起一行。Simy 没有值管道——见[控制流与作用域](/zh/reference/control-flow#execute-上下文作用域)。

## 从 Minecraft 本身借了什么

Simy 里最大的那套词汇其实和编程语言无关，而来自 Minecraft 自己：

- **命令**保持原样：`effect give $player minecraft:glowing 1 1`。
- **选择器与坐标**原样书写（`@a[gamemode=adventure]`、`~ ~1 ~`），`scoreboard`、`storage` 与 NBT 就是真实的存储模型，不藏在游戏并不存在的抽象后面。
- **领域类型**——`entity`、`selector`、`pos`、`vec3`、`block`、`item`、`team`、`tag`、`nbt`——都是一等类型。

`nbt` 逃生舱保证 DSL 永远不会被 MC 新版本的新字段卡住：任何无法抽象的东西都能以原始 NBT 传递。

## 如果你已经会另一门语言

| 概念        | Rust                     | Python          | Kotlin                 | Simy                            |
| :---------- | :----------------------- | :-------------- | :--------------------- | :------------------------------ |
| 块          | `{ }`                    | 缩进            | `{ }`                  | `{ }`                           |
| 语句结尾    | `;`                      | 换行            | 换行（`;` 可省略）     | 换行                            |
| 变量        | `let`，默认不可变        | `x = …`，可变   | `val`（不可变）/ `var` | `let`，默认不可变               |
| 类型        | 检查，写在名字后         | 仅提示          | 检查，写在名字后       | 检查，写在名字后                |
| 返回        | `return`，或最后表达式   | `return`        | `return`，或表达式体   | `return`，或最后表达式          |
| `if` 产生值 | 是                       | 否（是语句）    | 是                     | **是**                          |
| 空值        | `null` / `Option`        | `None`          | `null` / `T?`          | `option<T>`                     |
| 循环        | `for` / `while` / `loop` | `for` / `while` | `for` / `while`        | `repeat` / `while` / `for … in` |

## 我们刻意丢弃的 Rust 语法

不可能全盘照搬 Rust 语法。我们希望在 Simy 代码规范易维护的前提下简化语法，让非职业程序员也能轻松学会它

| Rust                                       | Simy                                               | 原因                                          |
| :----------------------------------------- | :------------------------------------------------- | :-------------------------------------------- |
| `println!(…)` 宏 + 格式串 + 各种格式化选项 | Python 那样直白的 `print` 调用，**不提供参数选项** | 打印一个值，不该先学宏和格式串                |
| `else if` 多层分支                         | `elif`（**借鉴自 Python**）                        | 更短，且每个分支都保持在同一缩进层级          |
| 每条语句末尾的 `;`                         | 语句以**换行**结尾                                 | 少记一条标点规则；一行一句                    |
| 所有权、借用、生命周期                     | 全部移除                                           | 根本没有内存要管理                            |
| `struct` + `impl` + `trait`                | `component`（状态 + 行为）                         | 只保留 Minecraft 真正需要的形状               |
| 宏（`!`）                                  | 无                                                 | 没有元编程要学                                |
| `pub`、`mod`、`use`、crate                 | 不需要                                             | 数据包就是一套扁平的文件布局 + 生成的命名空间 |
| 到处是泛型                                 | 仅 `list<T>`、`map<k, v>`、`option<T>`             | 够表达真实数据，又不会变成类型体操            |
| `match`、枚举、闭包、迭代器                | 暂不提供                                           | 保持表层语法足够小                            |

## 我们遵循的准则

> **留下让代码可读的「结构」，丢掉只在系统编程里才划算的「仪式」。**

Rust 给了形状，函数式语言与 Revo 给了表达式化的写法，Python 给了小巧的工效学，Minecraft 给了词汇；纯粹为了让一门内存安全的系统语言运转起来才存在的东西，全部去掉。

## DSL 就在你我身边

人们容易用「能表达多少东西」来衡量一门语言，而 Simy 刻意反其道而行——但它并不孤单。计算机领域里最有影响力的语言，很多都不是通用语言：

- **HTML** 描述文档；
- **SQL** 查询数据库；
- **Excel 公式** 计算表格；
- **CSS** 为网页排版；
- **正则表达式** 匹配文本；
- **Makefile / Dockerfile / .gitignore** 配置工具。

它们都很小、很专注，而且刻意**不是图灵完备**的；每一个都为某个领域打开了大门，让不是职业程序员的人也能上手。DSL 并不是「差一等的通用语言」，而是一种不同的工具——在它擅长的领域里往往更好用。Simy 很自豪成为中之一。
