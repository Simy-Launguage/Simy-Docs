# 设计原则

Simy 围绕五条原则设计，它们解释了你在[参考](/zh/reference/lexical)里看到的大部分表层语法决策。

| 原则                          | 说明                                                    |
| :---------------------------- | :------------------------------------------------------ |
| **默认不可变，可变显式标记**  | 不可变无前缀；可变加 `mut` 前缀，异常情况视觉上“有标记” |
| **减少书写量**                | `fn`、条件免括号、`const` 编译期内联                    |
| **类型后置**                  | `name: Type`，可推断时省略                              |
| **结构化替代 `execute` 嵌套** | 控制流与作用域块替代原生 `execute` 复杂语法             |
| **贴近 Minecraft 概念**       | 实体、方块、物品、计分板、storage 作为一等公民          |

## 默认不可变，可变显式标记

数据包里大部分值都是配置或中间结果，永远不会变。因此 Simy 默认把它们当作不可变，
只有你显式要求时才可变：

```simy
let damage = 10      // 不可变
let mut timer = 0    // 可变 —— 需要声明存储位置
const MAX_HEALTH = 20
```

大体上约 **80%** 的绑定是不可变的，**20%** 是可变。由于可变绑定必须声明它存在哪里，
扫描代码时程序里“有状态”的部分会格外显眼。详见[变量与类型](/zh/reference/variables-and-types)。

## 减少书写量

- `fn` 与 `component` 是你唯一需要记的代码声明关键字。
- 条件**免括号**，块用 `{ }` 界定。
- `const` 在编译期彻底内联，不占运行时存储。
- 语句以**换行**结尾（Python 风格），不靠标点符号。

## 类型后置

类型写在绑定名**后面**，能推断时可省略：

```simy
let target: entity = @e[type=creeper]
let damage = 10                  // 推断为 num
```

详见[类型系统](/zh/reference/variables-and-types)。

## 结构化替代 `execute` 嵌套

原生数据包逻辑把 `execute` 子句层层嵌套，超过两层就很难读。Simy 改用普通的控制流
（`if`、`for`、`while`）以及一个结构化的 `execute` 作用域，目标写在 `< … >` 中：

```simy
execute at <@a> {
    particle minecraft:heart ~ ~1 ~ 0.5 0.5 0.5 0.1 10
}
```

详见[控制流与作用域](/zh/reference/control-flow)。

## 贴近 Minecraft 概念

实体、方块、物品、坐标、队伍、标签与原始 NBT 都是**一等类型**，而不是不透明的字符串。
这让编译器能对它们推理、做更激进的优化；同时 `nbt` 仍作为逃生舱，承载尚未建模的部分。
